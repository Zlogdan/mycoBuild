# Этап 1. Исследование источников игровых данных

Дата: 2026-11-09 · Версия игры: Steam-сборка, Unity 6000.4.12f1 (Mono), установлена в `C:\Program Files (x86)\Steam\steamapps\common\Mycopunk`.

## 1. Итог

**Все нужные данные удалось достать автоматически из файлов игры**, без вики и ручного ввода:
геометрия модов, редкость, флаги, характеристики (диапазоны значений), иконки, названия и описания на EN/RU,
список модов по оружию/персонажу, размеры сеток по уровням.
Правила (вращение, размер сетки, расширители) взяты из байткода игры (`Assembly-CSharp.dll`).

Результат: `site/public/data/game.json` (≈675 КБ) + `site/public/data/icons/*.png` (647 иконок).
Генератор: `extractor/extract.py` — повторный запуск после патча игры обновляет базу за ~5 секунд.

| Что | Количество |
|---|---|
| Персонажи (Bruiser, Glider, Mycologist, Scrapper, Wrangler) | 5 |
| Основное оружие | 13 |
| Тяжёлое оружие | 4 |
| Метательное (4 гранаты + Photon Disc) | 5 |
| Спец. (Broken Frame) | 1 |
| Общий пул модов персонажа (`player`, 41 мод) | 1 |
| Моды всего | 780 (773 привязаны к оружию/персонажу, 7 не привязаны) |

## 2. Источники и степень достоверности

| # | Источник | Что даёт | Достоверность |
|---|---|---|---|
| S1 | `Mycopunk_Data/resources.assets`, `sharedassets0.assets` — ScriptableObject'ы `GenericGunUpgrade`, `GenericPlayerUpgrade`, `*Upgrade`, `GearInfo`, `Character`, `GridProfile` | Моды, паттерны, редкость, флаги, характеристики, привязка к оружию, сетки | **Высокая** — это сами игровые данные |
| S2 | `Mycopunk_Data/Managed/Assembly-CSharp.dll` (IL-код, дизассемблирован) | Правила: система координат, вращение, проверка границ, рост сетки, разблокировка вращения | **Высокая** для прочитанных методов; выводы помечены ниже |
| S3 | TextAsset `TextBlocks` (CSV, 11 языков) | Названия/описания EN+RU, цвета ключевых слов (fire, shock…) | **Высокая** |
| S4 | Sprite'ы игры | Иконки модов и оружия | **Высокая** |

Как это читается: в сборке нет type tree, поэтому структуры восстанавливаются генератором типов из DLL
(`TypeTreeGeneratorAPI`) и читаются `UnityPy`. Поля `[SerializeReference]` (характеристики модов) потребовали
своего резолвера — реализован в экстракторе. Декомпилятор ILSpy запустить в этом окружении не дали
(блокировка запуска скачанного кода), поэтому правила читались через дизассемблер IL (`dncil`) — это медленнее, но надёжно.

## 3. Модель модификации (что есть в данных)

| Требуемое поле | Источник в игре | Статус |
|---|---|---|
| Идентификатор | `Upgrade.id` (int), `_name` (строковый ключ) | ✅ |
| Название / описание | `TextBlocks[_name]`, `TextBlocks[_description]` или `_name_1` / `_nameD` | ✅ (2 мода без описания и в игре: Party, Globblin) |
| Иконка | `Upgrade.icon` → Sprite | ✅ все 780 |
| Тип / редкость | `Rarity`: Standard, Rare, Epic, Exotic («золотые»), Oddity, Contraband | ✅ |
| Стихия | `effectType`: normal/fire/shock/acid/cryo/… | ✅ |
| Геометрический паттерн | `pattern: HexMap {width, height, nodes[y][x]{enabled, connections}}` | ✅ |
| Принадлежность | `GearInfo.upgrades[]` | ✅ |
| Дублирование | флаг `UpgradeFlags.CanStack` (56 модов) — в UI игры подпись «Накапливается/Stackable» | ⚠️ средняя, см. вопросы |
| Вращение | общие правила по редкости + уровень аккаунта (см. §4.3) | ✅ |
| Характеристики | `properties` → объекты `UpgradeProperty_*` с диапазонами `{min, max}` (в игре каждый экземпляр мода получает случайное значение из диапазона) | ✅ сырые данные; человекочитаемые подписи формируются кодом игры — см. §6 |

Размеры паттернов: 1 клетка — 5 модов, 2 — 23, 3 — 204, 4 — 300, 5 — 144, 6 — 66, 7 — 19, 8+ — 12.

**Важно:** 3 мода имеют **несвязный** паттерн (так в данных игры): `Makeshift Barrel`, `Multiball`, `Switcheroo`.
Т.е. правило «мод — это связные гексы» не абсолютное; алгоритм не должен на него полагаться.

## 4. Правила, подтверждённые кодом игры

### 4.1 Система координат
`HexMap.HexToCube / CubeToHex`: сетка хранится в **offset-координатах «odd-q»** — гексы с плоским верхом,
столбцы `x`, строки `y`, **нечётные столбцы сдвинуты вниз на половину ячейки**. Для поворотов игра переводит
в **кубические координаты** (`x, y=-x-z, z = row - (col - (col&1))/2`).

Биты `connections` (визуальные «дорожки» между гексами внутри мода): `1=N, 2=NE, 4=SE, 8=S, 16=SW, 32=NW`.

**Рекомендация:** хранить доску в offset (как в игре — прямоугольник W×H, просто отрисовывать и
экспортировать), а паттерны и все вычисления (вращение, сдвиг, пересечения) вести в **axial/cube** —
поворот на 60° там — перестановка координат `(x,y,z) → (−y,−z,−x)`, а сдвиг фигуры не зависит от чётности столбца.
Это ровно то, что делает игра.

### 4.2 Размер сетки
`GearInfo.GetUpgradeGridSize(level)` → `GridProfile.gridSizes` — берётся **уровень конкретного оружия / персонажа**
(`GearData.Level`), а не уровень аккаунта.

| Профиль | Кто использует | Уровень → W×H (столбцы × строки) |
|---|---|---|
| DefaultGridProfile | персонажи, основное, метательное | 0 → 5×5, 3 → 6×5, 6 → 6×6, 10 → 7×6 |
| HeavyGridProfile | тяжёлое оружие | 0 → 5×5 (не растёт) |
| BrokenFrameGrid | Broken Frame | 0 → 6×3 |

Проверка размещения (`GearData.CanEquipUpgrade`): только **все клетки фигуры внутри W×H**; пересечения проверяются
занятостью ячеек. Других ограничений по позиции (запрещённых ячеек) в коде нет — доска всегда полный прямоугольник.

### 4.3 Вращение — **расходится с ТЗ**
`PlayerData.UpdateRarityRotations` / `CanRotateUpgrade`: вращение открывается по **уровню аккаунта (игрока)**
**для каждой редкости отдельно**:

| Редкость | Вращение доступно с уровня аккаунта |
|---|---|
| Standard (зелёные) | 3 |
| Rare (синие) | 8 |
| Epic (фиолетовые) | 16 |
| Exotic (золотые) **и выше** (Oddity, Contraband) | 30 |

Шаг — 60°, 6 ориентаций. Зеркального отражения в коде нет. Есть также глобальный флаг `canRotateUpgrades`,
снимающий ограничения (вероятно, отладка/особый режим).

### 4.4 Расширение сетки — **частично расходится с ТЗ**
`UpgradeProperty_GrowGrid` + `GearData.ModifyGridSize`. В игре два таких мода (1 клетка каждый, оба `GenericPlayerUpgrade`):

| Ключ | Название RU | Редкость |
|---|---|---|
| GridGrow | Нарушение границ | Oddity |
| GridGrowC | Нечёткий край | Contraband |

- Каждый экземпляр даёт **+1 столбец или +1 строку**; что именно — определяется **случайным сидом экземпляра**
  (`AffectsColumn = new Random(seed).NextBool()`), а не типом мода.
- `ModifyGridSize` суммирует **все** установленные расширители — ограничения «только один» в этом методе нет
  (оно может быть в другом месте: дроп/уникальность — не нашёл).
- Ещё есть `GridThief` («Мультивселенский грабёж», Contraband): «забирает 1 столбец у каждой другой вашей сетки» —
  влияет на несколько предметов сразу.
- Эти 3 мода (и ещё 4 «способностных»: NoseDive, Jetpack, AirDash, Wingsuit/MycoUpgrade) **не перечислены ни в одном
  GearInfo** — механизм их выдачи не закодирован в данных. В базе они есть, с пустым списком `gears`.

### 4.5 Изменение паттерна в игре
`Upgrade.GetPattern`: паттерн экземпляра может отличаться от базового:
- мод «Карманная вселенная» (`Cells`) переключает **все** моды на паттерны по редкости (1/2/3/4… клетки);
- «Pattern Infuser» может переопределить паттерн экземпляра чужим;
- `UpgradeProperty_Pattern` (1 мод, MIRV) задаёт альтернативный паттерн.
Базовые паттерны в базе — достоверны; эти особые случаи — отдельная задача.

### 4.6 Пространственные моды (флаг `IsSpatial`, 16 шт.)
Эффект зависит от соседей: например «Самохранение» — магазин растёт за каждую занятую соседнюю клетку и
падает за пустую; «Полный спектр» — бонус за соседей разной редкости; призмы Gunship Cannon и т.д.
Это влияет на оценку раскладки, но не на допустимость.

## 5. Структура `game.json` (кратко)

```
meta          — версия, дата извлечения, описание системы координат
rarities[]    — id, key, name{en,ru}, color
effects{}     — стихии с локализацией
keywords[]    — слова для подсветки в описаниях (+цвет)
gridProfiles{} — профиль → [{level, w, h}]
gears[]       — id, key, category(character|primary|heavy|throwable|special|global), name, icon, grid, upgrades[ids]
upgrades{id}  — id, key, name, desc, rarity, flags[], effect, source, icon,
                pattern{w,h,cells:[[x,y,connections]]}, altPatterns[], props[{type,data}], gears[]
```

## 6. Чего нет / что потребует ручной работы

1. **Человекочитаемые характеристики.** Данные есть (`fireRate: 1.05–1.06`, `maxStacks: 4`), но подписи и формат
   («+5–6% скорострельности») генерирует код каждого из ~530 классов `UpgradeProperty_*`. Варианты: показывать сырые
   значения с авто-подписями из имён полей, либо постепенно писать словарь форматирования.
2. **Цвета Oddity/Contraband** — не нашёл в текстах; сейчас подобраны вручную (помечено в экстракторе).
3. **Уровни аккаунта, после которых меняется что-либо кроме вращения**, — не исследовал (не требуется).
4. **Правило дублирования** — см. вопросы.
5. **Выдача расширителей сетки** (к какому оружию можно поставить) — в данных нет.
