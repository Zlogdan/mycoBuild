# Этап 6. Сверка с игрой на реальных билдах

Источник: сохранение игрока `PlayerData.saxon` (.NET BinaryFormatter, без шифрования). Сайт читает его
модулем `site/src/core/save/` (разбор MS-NRBF + перевод координат игры). Файл сохранения в репозиторий
не добавляется (`*.saxon` в `.gitignore`); тест на нём запускается только с `MYCO_SAVE=<путь>`.

## Что содержит сохранение (используется)

| Поле | Что это |
|---|---|
| `upgradeRarityRotations` | битовая маска открытых вращений по редкостям → уровень аккаунта 3 / 8 / 16 / 30+ |
| `collectedGear[gearId].level` | уровень каждого оружия / персонажа |
| `collectedGear[gearId].equippedUpgrades` | текущая раскладка: `upgradeID` (id **экземпляра**), `x`, `y`, `rotation` |
| `collectedGear[gearId].loadouts[0..2]` | три сохранённых лоадаута в том же формате |
| `data[gearId][].Instances[]` | экземпляры модов: id, id мода, `Seed`, `patternSize`, `overriddenPatternID` |

## Перевод координат игры

Игра хранит позицию мода не так, как сайт: якорь смещён на половину ширины повёрнутой карты, плюс поправки по
чётности столбцов. Перенесены буквально из IL:
`HexMap.GetModifiedMap` / `CalculateRotatedSize` / `AdjustRow` и `GearData.CanEquipUpgrade` → `gameFootprint()`.

Направление расширителя (`UpgradeProperty_GrowGrid.AffectsColumn`) вычисляется из `Seed` экземпляра портом
игрового `Random` (`state = seed`, хеш-шаг `Next`, `NextBool` = нечётность) → `growGridDirection()`.

## Результаты

| Проверка | Результат |
|---|---|
| Форма каждого из 775 паттернов в 6 поворотах и 15 позициях по формуле игры = форма на сайте | **совпадает** (≈70 000 проверок) |
| Реальных билдов в сохранении (текущие + лоадауты) | 34 |
| Перевод всех 34 билдов без расхождения формы | **да** |
| Текущие (надетые) билды проходят все правила сайта | **да, все** |
| Лоадауты с замечаниями | 2 из 30: «Свинцемёт» (мод вне сетки 6×5 на 5-м уровне), «Гальваническая граната» (пересечение) |
| Расширитель: билд «Прыгострела» 7×6 + расширитель → 7×7, все 49 клеток заняты | **корректен** — направление из сида (строка) подтверждено |
| Уровень аккаунта по маске вращений | 30+ |

Почему два лоадаута с замечаниями — не ошибка модели: `GearData.EquipLoadout` для каждого мода вызывает
`CanEquipUpgrade` / `EquipUpgrade` и при неудаче показывает сообщение `cantequip`. То есть игра сама допускает
устаревшие лоадауты (сохранённые до изменений паттернов или на другой раскладке) и пропускает неподходящие моды.
Сайт восстанавливает такой лоадаут как есть и подсвечивает проблемные моды.

## Открытые вопросы

1. У 12 из 1265 экземпляров `patternSize` в сохранении отличается от числа клеток паттерна в текущих данных
   (например, GlobPuddle: 9 против 5). Вероятно, паттерн экземпляра изменён свойствами мода (`ModifyPattern`) или
   данными старой версии игры. Сайт использует базовый паттерн; для точного учёта нужно разобрать
   `UpgradeProperty.ModifyPattern` у этих модов.
2. 15 экземпляров имеют `overriddenPatternID` (Pattern Infuser). Сайт пока игнорирует переопределение.
3. Значения характеристик конкретного экземпляра выводятся из `Seed` — можно показывать точные числа вместо
   диапазонов для импортированных билдов (нужен порт `Upgrade.ModifyPropertySeed` и чтения диапазонов).
